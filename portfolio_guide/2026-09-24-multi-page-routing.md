# 2026-09-24 - Split into Home / About / Projects pages

## The "Why" (Design Decisions)

The site was a single scrolling page (Hero → About → Projects → Footer, all in one `App.jsx`). The request was to give Projects and About their own pages, keep Hero as the landing experience, add a Hero button to About, and make the `Data Specialist | Finance | Engineer` filter clickable only on the Projects page.

**Hash routing, not clean URLs.** The site deploys to GitHub Pages as a static bundle (`.github/workflows/deploy.yml` is a plain `upload-pages-artifact` + `deploy-pages`, no server-side rewrite capability). Clean URLs (`/about`, `/projects`) would 404 on a direct link or a refresh, because GitHub Pages has no server to redirect unknown paths back to `index.html` - that's normally solved with a `404.html`-redirects-to-`index.html` trick, which is extra surface area to maintain. `HashRouter` sidesteps the whole problem: everything after `#` never reaches the server at all, so `/#/about` always resolves to the same static `index.html` GitHub Pages already serves for `/`. Confirmed with the user this trade (uglier URLs, zero extra deploy config) was the right one for a portfolio site.

**This unlocked a real simplification, not just a routing add.** The `.page-content` full-bleed-opaque-background trick (from the earlier 3D-wave-grid work) existed only to occlude the fixed wave-grid canvas once a single long page scrolled past Hero into About/Projects/Footer. Once Hero/About/Projects became separate *routes*, React Router unmounts Hero - and therefore `WaveGridBackground`, and therefore the whole Three.js scene via its existing `Orchestrator.destroy()` - the instant you navigate away from `/`. About and Projects never have the canvas mounted at all now, so the elaborate occlusion CSS that used to cover all three sections shrank down to just wrapping Footer on the Home page. Less CSS, and it's correct by construction (nothing to occlude if nothing's there) rather than by careful z-index bookkeeping.

**Filter state moved down, not sideways.** Previously `App.jsx` lifted `pinnedCategory`/`hoveredCategory` state so both Hero and Projects could share one filter selection. Now that Hero shows the categories as plain static text (per the request), nothing needs to share that state anymore - it moved from `App.jsx` into `Projects.jsx` as local state, and `App.jsx` went back to being pure routing with no state of its own. This is the same logic as before, just owned by the one place that still uses it.

## Core Concepts

**`HashRouter` vs `BrowserRouter`.** Both are client-side routers from `react-router-dom`; the difference is only *where* the current route lives - `BrowserRouter` uses the real URL path (needs server cooperation to handle direct loads to a sub-path), `HashRouter` encodes it in the URL fragment (`#/about`), which browsers never send to the server on their own, so it works against any static file host with zero configuration. `HashRouter` doesn't need Vite's `base: '/portfolio/'` config threaded into it (no `basename` prop) - that setting only rewrites *asset* paths at build time; the router's route matching is entirely independent of it, since it only ever looks at the part after `#`.

**Route-driven unmount as a lifecycle guarantee, not just a tree change.** `WaveGridBackground`'s Three.js scene was already written to construct fresh and fully tear down on unmount (for React 19 StrictMode's dev-only double-invoke). Routing turns that same code path into something that runs constantly during real usage - every Home→About, About→Home, Home→Projects transition is a genuine mount/destroy cycle now, not a one-off page-load event. It was verified directly (not assumed “it probably still works”): navigated Home→About→Home→Projects→Home five times in a row in a real browser and confirmed exactly one `<canvas class="wave-grid-canvas">` element ever exists at a time and no console warnings accumulate.

**A real bug this verification surfaced:** `Orchestrator.js` was using `THREE.Clock`, which three.js has deprecated in favor of `THREE.Timer` (the latter also integrates with the Page Visibility API via `.connect(document)`, avoiding a large delta-time spike if a tab is backgrounded and resumed - which matters more now than before, since navigating away from Home and back is a normal interaction, not just an occasional tab switch). This was pre-existing before today's routing work, just newly visible because the mount/unmount cycle now runs repeatedly instead of once. Fixed by swapping to `Timer` and calling `.update()` once per frame before reading `.getDelta()`, plus `.disconnect()`/`.dispose()` in `Orchestrator.destroy()`.

## Implementation Breakdown

- `client/src/main.jsx` - wraps `<App/>` in `<HashRouter>` (inside `<StrictMode>`, so every descendant has router context).
- `client/src/App.jsx` - now just `<main><Routes>...</Routes></main>`, no state.
- `client/src/pages/{Home,AboutPage,ProjectsPage}.jsx` - thin per-route compositions of the existing section components plus `<Footer/>`, each setting `document.title` in a 3-line inline `useEffect` (not worth a shared hook for three call sites).
- `client/src/components/layout/BackLink.jsx` - a small shared `<Link to="/">`, used identically on AboutPage/ProjectsPage since a visitor landing there directly (shared link, refresh) has no other way back to Hero.
- `client/src/components/sections/Hero.jsx` - dropped the `CategoryFilter` component entirely in favor of static text (`{CATEGORIES.join(' | ')}`, reusing the existing `data/projects.js` constant); "See my work" and the new "About" CTA are now `<Link>`s instead of anchors.
- `client/src/components/sections/Projects.jsx` - owns its own `pinnedCategory`/`hoveredCategory` state locally; `CategoryFilter.jsx` itself is unchanged, it's still the same presentational component, just with a single consumer now instead of two.
- `client/src/index.css` - the `.about, .projects, .footer` shared centering rule shrank to just `.footer`; `.about`/`.projects` dropped their `border-top` (each is now the top of its own page, not a section preceded by another one); added `.page-back` for `BackLink`.
